# 1. 项目概述

## 1.1 项目名称

记账助手（AI Budget Assistant）

---

## 1.2 产品定位

记账助手是一款基于大语言模型的个人财务管理 AI Agent。

用户无需填写复杂表单，只需要通过自然语言与 Agent 对话，即可完成：

* 消费记录
* 自动分类
* 历史账单查询
* 消费统计
* 消费分析
* 预算规划

Agent 通过 MySQL 保存用户的历史财务数据，使其具备长期记忆能力。

未来可以进一步通过移动端 App 为用户提供完整的个人财务管理体验。

---

## 1.3 产品核心理念

传统记账工具：

```text
用户填写表单
        ↓
保存账单
```

本项目：

```text
用户自然语言
        ↓
AI理解
        ↓
Agent调用工具
        ↓
数据库长期记忆
        ↓
AI分析
        ↓
自然语言反馈
```

核心目标不是简单地“记录账单”，而是构建：

> 一个能够理解用户、记住用户历史消费并基于历史数据提供财务建议的 AI 财务助手。

# 2. 用户分析

## 2.1 目标用户

主要面向：

* 希望记录日常消费的年轻用户
* 希望控制消费支出的学生
* 刚参加工作的职场新人
* 希望了解消费习惯的个人用户

---

## 2.2 用户痛点

| 痛点   | 描述                 |
| ---- | ------------------ |
| 记录麻烦 | 传统记账需要填写多个字段       |
| 容易遗忘 | 消费后经常忘记记录          |
| 不会分析 | 只能看到金额，不知道消费结构     |
| 缺少规划 | 不知道如何制定合理预算        |
| 数据孤立 | 传统工具的数据与智能分析能力结合不足 |

# 4. 产品功能设计

# 4.1 AI聊天记账（P0）

## 功能描述

用户通过自然语言描述消费。

Agent 自动提取：

* 消费名称
* 金额
* 分类
* 消费时间

---

## 用户输入

```text
今天早餐4元，公交4.5元，网易云会员5元
```

---

## Agent解析

```json
{
  "expenses": [
    {
      "category": "餐饮",
      "amount": 4,
      "description": "早餐",
      "time": "今天"
    },
    {
      "category": "交通",
      "amount": 4.5,
      "description": "公交",
      "time": "今天"
    },
    {
      "category": "娱乐",
      "amount": 5,
      "description": "网易云会员",
      "time": "今天"
    }
  ]
}
```

---

## 功能要求

### 多笔消费

支持：

```text
午饭20，奶茶8，打车15
```

解析为3条消费记录。

---

### 时间识别

支持：

```text
昨天晚上吃火锅68
```

解析：

```text
category：餐饮
amount：68
time：昨天
```

---

### 信息不足处理

用户：

```text
买衣服了
```

Agent：

```text
请告诉我购买金额，我才能帮你记录。
```

---

# 4.2 自动消费分类（P0）

默认分类：

| 分类 | 示例       |
| -- | -------- |
| 餐饮 | 早餐、外卖、火锅 |
| 饮品 | 奶茶、咖啡、饮料 |
| 交通 | 公交、地铁、打车 |
| 购物 | 衣服、日用品   |
| 娱乐 | 游戏、会员、电影 |
| 学习 | 书籍、课程    |
| 住房 | 房租、水电    |
| 医疗 | 药品、医院    |
| 其他 | 无法判断     |

---

# 4.3 数据持久化 / 长期记忆（P0）

Agent 解析消费后，将结构化数据保存到 MySQL。

例如：

```text
用户：

今天午饭15元
```

Agent：

```text
解析
 ↓
餐饮 / 15 / 午饭 / 今天
 ↓
保存MySQL
```

数据库成为 Agent 的长期记忆。

---

# 4.4 智能账单查询（P0）

用户可以通过自然语言查询历史数据。

例如：

```text
我这个月花了多少钱？
```

Agent：

```text
本月共消费 487.5 元。

其中：

餐饮：250元
交通：80元
购物：100元
娱乐：57.5元
```

---

支持：

* 月度查询
* 日度查询
* 时间范围查询
* 分类查询
* 金额查询

例如：

```text
我昨天花了多少钱？

这个月餐饮花了多少？

我上周买东西花了多少钱？
```

---

# 4.5 消费统计（P0）

Agent 根据数据库数据计算：

* 总消费金额
* 消费笔数
* 分类金额
* 分类占比
* 日均消费

---

# 4.6 消费分析（P1）

Agent 不仅返回数据，还进行解释。

例如：

```text
我这个月花了多少钱？
```

Agent：

```text
本月共消费 2500 元。

其中餐饮占 48%，是最大的支出类别。

相比上个月，餐饮支出增加约 180 元。

如果希望降低支出，可以优先控制外卖和饮品消费。
```

---

# 4.7 预算规划（P1）

用户：

```text
我每个月生活费3000元，帮我制定预算。
```

Agent 根据用户收入、固定支出以及历史消费生成预算建议。

例如：

```text
建议月预算：

餐饮：1000元
交通：200元
娱乐：300元
学习：300元
其他：200元
储蓄：1000元
```

# 5. AI Agent设计

## 5.1 Agent核心职责

Agent主要负责：

1. 理解用户自然语言
2. 判断用户意图
3. 提取结构化数据
4. 调用外部工具
5. 查询历史数据
6. 分析消费情况
7. 生成自然语言回复

---

## 5.2 Agent能力

当前规划：

```text
              AI财务Agent
                    |
        -------------------------
        |           |           |
       记账        查询        分析
        |           |           |
     MySQL       MySQL       MySQL
```

---

## 5.3 Agent工具

Agent通过工具访问外部系统。

第一阶段工具：

```text
save_expense
```

作用：

保存消费记录。

---

第二阶段：

```text
query_expenses
```

作用：

查询历史消费。

---

第三阶段：

```text
analyze_expenses
```

作用：

获取统计数据。

# 6. Memory与数据库设计

## 6.1 为什么需要数据库

LLM本身不适合作为长期财务数据存储。

因此采用：

```text
LLM
负责理解和推理

MySQL
负责事实数据和长期记忆

FastAPI
负责提供数据访问工具
```

---

## 6.2 核心数据

第一阶段核心表：

```text
expenses
```

字段：

```text
id
user_id
category
amount
description
expense_time
created_at
```

---

## 6.3 长期扩展

未来增加：

```text
users
expenses
income
budgets
financial_goals
user_preferences
```

用于形成更完整的个人财务画像。

# 7. 用户流程设计

## 7.1 AI记账流程

```text
用户输入
    ↓
Agent理解
    ↓
提取消费信息
    ↓
判断是否需要补充信息
    ↓
调用save_expense
    ↓
MySQL保存
    ↓
Agent返回结果
```

---

## 7.2 AI查询流程

```text
用户问题
    ↓
Agent判断意图
    ↓
调用query_expenses
    ↓
MySQL查询
    ↓
Agent分析数据
    ↓
自然语言回答
```

---

## 7.3 AI分析流程

```text
用户问题
    ↓
Agent判断意图
    ↓
调用统计工具
    ↓
MySQL聚合查询
    ↓
LLM分析
    ↓
生成消费建议
```
